# 五子棋 · 在线对战

纯静态的单页五子棋，两个人打开同一个链接就能远程对战。没有服务器、没有数据库、不需要注册。

## 访问密码

站点带一道密码门，校验在浏览器里完成（`src/auth.ts`）。

> **这是帘子，不是锁。** 前端代码可读，懂技术的人能绕过。它挡住的是随手点进来的陌生人，不适合保护任何有价值的东西。密码不要复用别处的。

- 解锁后会在这台设备记住 30 天，刷新不用重输。
- 对局页的「锁定」按钮会立刻清除凭证并回到密码页。
- 密码在打包进 bundle 时只保留 SHA-256 哈希；改密码要同时改 `src/auth.ts` 里的 `PASS_HASH` 并重新构建。
- 未解锁时**不会**建立房间、也不会连接 MQTT broker。

## 房间绑定

一个房间属于「创建者 + 一个固定对手」这一对。

- A 创建房间、B 走进来之后，这个房间就绑定到 (A, B)。
- 之后**任何人**打开 A 的房间，都会被当作 B —— 不管用什么名字、在什么设备上。
- B 创建的房间同理，绑定到 (B, A)。
- 双方在商店里能看到彼此的积分和持卡数。

绑定记录存在 MQTT retained 主题 `gomoku-v1/pair/<创建者名字>` 上，首次建立后不再改写。

## 怎么玩

1. 打开页面，填昵称，点「创建新房间」。
2. 点侧栏的「复制」，把链接发给朋友。
3. 朋友打开链接，会自动坐到空着的座位上（先到先黑棋）。
4. 轮流落子。棋盘上红圈标出对手刚下的那一步，五连时红线标出获胜连子。

想观望也可以：直接打开房间链接的第三个人会坐在观战席，看得到全部棋盘和落子记录。

## 实现方式

同步靠 **MQTT 公共 broker**（`broker.emqx.io`，失败时切 `test.mosquitto.org`）的 **retained 消息**，房间码就是 topic 名：

```
gomoku-v1/<房间码>/state   ← 一条 retained JSON，存整个房间的权威状态
```

这条 retained 消息里放着 `hist`（全部落子）和 `seats`（谁坐哪边）。因为 broker 会替最后一个订阅者保存它，所以：

- **迟到加入**：订阅瞬间就收到当前棋盘，不需要"请求同步"。
- **断线重连**：同理，重连后立刻恢复现场。
- **无需数据库**：状态只有一条消息，天然没有历史堆积问题。

棋盘本身不传输，两端各自用 `replay(hist)` 重算——所以只要 `hist` 一致，两端画面必然一致。

### 并发冲突怎么办

每个改动都是一次「全量快照 + `rev + 1`」发布，收到的快照按 `rev` 大者胜。两个人几乎同时落子会产生相同的 `rev`，这时用 `writer`（客户端 id）做确定性仲裁——两端比的是同一个值，所以会收敛到同一份历史，而不是各留各的。

### 已知边界

- **公共 broker**：任何人都能订阅任意 topic，房间码是 6 位（32 字符表，约 10 亿种）防止撞车，但不是加密信道。别在里面放敏感信息。
- **没有裁判**：规则校验在各自浏览器里做（合法落子、轮次、胜负），朋友之间对弈够用。要防作弊得上后端。
- **broker 可用性**：依赖第三方公共服务，偶尔会有延迟或限流。这是"零后端"的代价。
- **清场**：房间的 retained 消息会留在 broker 上，直到有人写入新状态。开局时会覆盖，不影响使用。

## 开发

```bash
npm install
npm run dev      # 开发服务器
npm run build    # 构建到 dist/
npm run preview  # 本地预览构建产物
node --test src/board.test.ts   # 规则单测
```

> Windows 提示：如果工作区在目录联接（junction）下，请在真实路径上执行 `vite build`，否则 Rollup 会因为路径解析不一致而报 chunk 名错误。

## 部署到 WorkBuddy Studio（静态托管）

`npm run build` 产出的 `dist/` 就是全部内容，纯静态文件：

```
dist/index.html
dist/assets/index-*.js
dist/assets/index-*.css
```

步骤：

1. 本地跑 `npm run build`。
2. 把 **`dist/` 目录里的内容**（不是 `dist` 这个文件夹本身）上传到 Studio 的静态站点根目录。
3. 确认入口是 `index.html`。

因为路由用的是 `#` 哈希（`https://…/#/r/ABC-DEF`），**不需要任何服务端重写规则**，放在子路径下也能正常工作（`vite.config.ts` 里设了 `base: './'`）。

### 部署后自检

打开站点应该先看到密码页。输对密码后进大厅，创建房间地址栏变成 `#/r/XXXXXX`，侧栏显示「已连接」。用手机开同一个链接，两边应该互相看得到对方昵称，落子实时同步。

如果一直显示「连接中 / 连接异常」，多半是所在网络屏蔽了 `broker.emqx.io:8084` 的 WSS——页面会自动尝试备用 broker；公司网络或某些校园网可能两个都不通。

> **WorkBuddy 注意**：它的静态站不会自动同步工作区文件，改完 `dist/` 必须在 WorkBuddy 里重新发布一次才会上线。
